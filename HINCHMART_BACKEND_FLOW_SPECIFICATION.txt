1. MASTER ARCHITECTURE & END-TO-END WORKFLOWS
================================================================================

1.1 FLOW 1: EXISTING SELLER MOBILE OTP LOGIN
--------------------------------------------
[Step 1: Enter Mobile Number]
  - Prefix: +91 | 10-digit Indian Mobile Number
  - Action: User clicks [ Check Account ] (Note: NOT Send OTP directly)
  - Helper: "We will check if your account exists."
       │
       ▼ POST /auth/check-account { mobileNumber: "9876543210" }
[Step 2: Account Check (Backend Verification)]
       │
       └──▶ [ Account Exists: TRUE ]
               │
               ▼ Displays: "Account Found! We will send you OTP."
               ▼ Action: User clicks [ Proceed to OTP ] (or auto-triggers)
               ▼ POST /auth/send-otp { mobileNumber: "9876543210" }
[Step 3: Send OTP & Enter OTP]
  - 6-digit OTP delivered via SMS Gateway / Firebase Phone Auth
  - UI renders 6 individual boxes (_ _ _ _ _ _)
  - Timer: 45s countdown + Resend OTP
  - Action: [ Verify OTP ]
       │
       ▼ POST /auth/verify-otp { phone: "9876543210", otp: "123456" }
[Step 4: Verify OTP & Profile Check]
  - Backend verifies OTP code against session record
  - Generates JWT Bearer Token
  - Checks seller profile status:
      - Profile Complete ──▶ UI shows "OTP Verified ✓" ──▶ Redirects to /seller/dashboard
      - Profile Incomplete ──▶ Redirects to missing registration section


1.2 FLOW 2: NEW SELLER REGISTRATION (NO OTP BEFORE ACCOUNT CHECK)
-----------------------------------------------------------------
[Step 1: Enter Mobile Number]
  - User enters un-registered mobile (e.g. 9123456789)
  - Clicks: [ Check Account ]
       │
       ▼ POST /auth/check-account { mobileNumber: "9123456789" }
[Step 2: Account Check (Backend Verification)]
       │
       └──▶ [ Account Exists: FALSE ]
               │
               ▼ CRITICAL BUSINESS RULE: DO NOT SEND OTP AT THIS STAGE!
               ▼ UI Displays Red Alert State:
                 🔴 Account Not Found
                 "This mobile number is not registered with HinchMart."
                 "Please register your business to continue."
               ▼ Primary Action: [ Register Your Business ]
                 (Navigates to /register with mobile number prefilled)

[Step 3: Multi-Step Registration Wizard]
  ├─▶ Step 2.1: Personal & KYC Details
  │     - Full Name * (Letters and spaces only, min 2 chars)
  │     - Mobile Number * (+91, 10 digits, prefilled)
  │     - Official Business Email * (Valid email RFC format)
  │     - Aadhaar Number * (Exactly 12 numeric digits)
  │     - PAN Card Number * (10 alphanumeric uppercase: ABCDE1234F)
  │     - Upload PAN Card * (JPG, PNG, PDF max 10MB via POST /documents/upload)
  │
  ├─▶ Step 2.2: Business & Tax Details
  │     - Business / Company Name * (Non-empty)
  │     - Business Classification * (Manufacturer, Distributor, Wholesaler, etc.)
  │     - GSTIN * (15 chars statutory GST format: 29ABCDE1234F1Z5)
  │     - Business Address * (Full street / industrial address)
  │     - State * (Select Indian state)
  │     - City * (City / District)
  │     - Pincode * (6 numeric digits)
  │
  ├─▶ Step 2.3: Bank & Settlement Details
  │     - Bank Name * (Letters and spaces only)
  │     - Account Holder Name * (Letters and spaces only)
  │     - Account Number * (8 to 20 digits)
  │     - Confirm Account Number * (Must match Account Number exactly)
  │     - IFSC Code * (11 uppercase alphanumeric: HDFC0000123)
  │
  ├─▶ Step 2.4: Verification & Documents (Review Checklist)
  │     - Summary Review:
  │       ✓ Personal Details (Complete)
  │       ✓ Business & Tax Details (Complete)
  │       ✓ Bank & Settlement Details (Complete)
  │       ✓ Documents Uploaded (Complete)
  │     - Action: [ Submit & Verify ]
  │
  └─▶ Step 2.5: Account Creation & Registration Successful
        - POST /auth/register (Atomic creation of seller, user auth, bank, and KYC records)
        - Verification Status initialized to: "Pending" (Admin Review Only)
        - UI renders Green Checkmark: "Registration Successful! Your seller account has been created."
        - Action: [ Go to Dashboard ] ──▶ Redirects to /seller/dashboard


1.3 FLOW 3: COMPLETE ORDER LIFECYCLE (NEW ──▶ COMPLETED)
--------------------------------------------------------
The lifecycle follows 10 distinct phases without skipping essential logistics stages:

                  BUYER ORDER
                       │
                       ▼
                    [ NEW ] ──────────── (Order placed by buyer, stock reserved)
                       │
                       ▼ PATCH /seller/orders/:id/status { status: "Confirmed" }
                 [ CONFIRMED ] ───────── (Seller accepted & confirmed order)
                       │
                       ▼ PATCH /seller/orders/:id/status { status: "Processing" }
                 [ PROCESSING ] ──────── (Picking, bundling & weight test)
                       │
                       ▼ PATCH /seller/orders/:id/status { status: "Ready for Dispatch" }
              [ PACKED / READY ] ─────── (Bundled with IS tags at warehouse bay)
                       │
                       ▼ (Mandatory Invoice check before dispatch)
             [ INVOICE GENERATED ] ───── (Statutory Commercial Tax Invoice created)
                       │
                       ▼ POST /seller/orders/:id/dispatch
                 [ DISPATCHED ] ──────── (Handed over to carrier with vehicle & driver info)
                       │
                       ▼ PATCH /seller/orders/:id/status { status: "In Transit" }
                 [ IN TRANSIT ] ──────── (Live GPS / Docket tracking en route to site)
                       │
                       ▼ PATCH /seller/orders/:id/status { status: "Delivered" }
                  [ DELIVERED ] ──────── (Delivered at buyer site address)
                       │
                       ▼ POST /seller/orders/:id/pod
                [ POD CONFIRMED ] ────── (Site Engineer signed GRN / Proof of Delivery uploaded)
                       │
                       ▼
                  [ COMPLETED ] ──────── (Order finished, payment settled to seller)


1.4 FLOW 4: INVOICE VS E-WAY BILL RULE (DISPATCH WORKFLOW)
----------------------------------------------------------
In the Seller Portal:
  1. Commercial Tax Invoice is MANDATORY before Dispatch.
  2. If Invoice is missing: Seller must click [ Generate Invoice ].
  3. Duplicate Prevention: Once generated, the invoice number (INV-YYYY-XXXXX) is permanent.
  4. E-Way Bill is NOT a mandatory Seller dispatch UI dependency in this workflow.
  5. The Dispatch modal collects Carrier Name, Vehicle Number, Driver Contact, Tracking Number, and Loading Notes, and automatically attaches the Commercial Tax Invoice.


1.5 FLOW 5: PRODUCT & CATEGORY LABELS WORKFLOW
----------------------------------------------
Product Labels are separate from Order Status.
  - Create Label: Label Name, Label Type (Badge, Tag, Banner), Color Scheme.
  - Predefined Labels: Bestseller, New Arrival, High Margin, Low Stock, Seasonal, Bulk Order, Fast Moving, Clearance.
  - Apply to Products: Bulk assign labels to selected products or categories.
  - Filter & Search: Enable buyers and sellers to filter catalogue by active product labels.

2.6 BANK METADATA & ACCOUNT NUMBER VALIDATION RULES (BANK-AWARE)
--------------------------------------------------------------------------------
Method: GET
URL: /api/v1/banks/metadata (Recommended Backend Endpoint)
Access: Public

Indian bank account numbers do not use a single fixed length. Account number validation must be bank-aware based on the selected Bank Name.

Bank Account Length Matrix:
--------------------------------------------------------------------------------
Bank Name                     Account Number Length / Range    Pattern
--------------------------------------------------------------------------------
HDFC Bank                     Exactly 14 digits                /^[0-9]{14}$/
ICICI Bank                    Exactly 12 digits                /^[0-9]{12}$/
State Bank of India (SBI)     11 to 17 digits                  /^[0-9]{11,17}$/
Axis Bank                     Exactly 15 digits                /^[0-9]{15}$/
Kotak Mahindra Bank           Exactly 10 digits                /^[0-9]{10}$/
Punjab National Bank (PNB)    Exactly 16 digits                /^[0-9]{16}$/
Bank of Baroda                10 to 14 digits                  /^[0-9]{10,14}$/
Canara Bank                   Exactly 13 digits                /^[0-9]{13}$/
Union Bank of India           Exactly 15 digits                /^[0-9]{15}$/
IndusInd Bank                 12 to 13 digits                  /^[0-9]{12,13}$/
Yes Bank                      Exactly 15 digits                /^[0-9]{15}$/
IDBI Bank                     Exactly 16 digits                /^[0-9]{16}$/
Bank of India (BOI)           Exactly 15 digits                /^[0-9]{15}$/
Central Bank of India         Exactly 10 digits                /^[0-9]{10}$/
Indian Bank                   9 to 10 digits                   /^[0-9]{9,10}$/
Federal Bank                  Exactly 14 digits                /^[0-9]{14}$/
IDFC FIRST Bank               11 to 12 digits                  /^[0-9]{11,12}$/
Other Scheduled Commercial    9 to 18 digits                   /^[0-9]{9,18}$/

Validation & Security Rules:
1. Input Restriction: Digits only (0-9). Reject letters, special characters, and spaces immediately upon keystroke/paste.
2. Dynamic Maximum Length: Set HTML maxLength dynamically matching the selected bank's maxLength.
3. Live Re-validation: When bank selection changes, re-validate account number against the new bank's rule.
4. Masking on Display: Mask account number on reviews and profiles (e.g. XXXXXX7890). Never expose full account numbers in logs or public responses.
5. Confirmation Check: confirmAccountNumber must match accountNumber exactly.

3.6 UPDATE ORDER STATUS
--------------------------------------------------------------------------------
Method: PATCH
URL: /api/v1/seller/orders/:id/status
Access: Protected (Bearer Token)

Request Payload:
{
  "status": "In Transit",
  "notes": "Consignment en route to site location"
}

Allowed Lifecycle Status Transitions:
- New ──▶ Confirmed
- Confirmed ──▶ Processing
- Processing ──▶ Ready for Dispatch
- Ready for Dispatch ──▶ Dispatched (via /dispatch)
- Dispatched ──▶ In Transit
- In Transit ──▶ Delivered
- Delivered ──▶ Completed (via /pod)
- New | Confirmed | Processing ──▶ Cancelled

Success Response (200 OK):
{
  "success": true,
  "message": "Order status updated to In Transit",
  "orderStatus": "In Transit"
}

--------------------------------------------------------------------------------

401 Unauthorized       INVALID_TOKEN          Missing or expired JWT Bearer token
403 Forbidden          PROFILE_INCOMPLETE     Seller profile missing required statutory fields

422 Unprocessable      INVALID_TRANSITION     Invalid status transition (e.g. New directly to Delivered)
500 Internal Error     INTERNAL_ERROR         Database or service failure
